01做过的几件事

商品发布 SDK

10+ 业务线
阿里巴巴 · 2016–2019

淘宝、天猫、盒马、飞猪的商品发布流程各不相同。我把通用流程抽成一套 SDK，各业务线用插件扩展配置协议、中间件和生命周期钩子，不用改核心代码。字段联动重复触发会形成死循环，就加了 Guard 机制来阻断。

政务低代码编辑器

编辑态 → 运行态
阿里云 · 2019–2021

编辑器只管选组件、排布局、配属性；字段联动、异步请求、安全控制和多端兼容交给运行时，两边靠编辑态到运行态的 Schema 转换连起来。事项中心用微前端交付给不同省市，各地的差异写进配置，不再维护独立分支。

菜鸟驿站前端治理

20 → 5 个仓库
菜鸟 · 2022–2024

接手时有 20 多个存量仓库，有几个已经发不了布。我按活跃度和迁移成本决定下线、迁移还是保留，最后收敛成 5 个；React、Vue 和组件库逐步统一，再用 AST 统计标准组件的引用覆盖率，看迁移走到哪一步。治理后，同类需求的评估工期缩短约 50%。

Agent 研发流程

20+ 位同事在用
字节跳动 · 2024 至今

基于 pi-core 写了一套 Multi-Agent 系统，按“PRD → 前端 TRD → TDD 生成代码”的顺序推进，关键步骤由人评审。另一个 Skill 用 Hooks 分析我和 Agent 的对话，把有用的结论提炼成 rules 和知识库文档，下一次任务直接用上，目前已沉淀 40 多条规则。

采购平台 LCP 治理

LCP −30%
字节跳动 · 2024 至今

先搭看板、定基线，再沿用户的核心访问链路，分前端、工作台和后端接口三层排查。内部用户的 LCP 从 4.5 秒降到 3.2 秒，外部用户从 6.7 秒降到 4.7 秒。
