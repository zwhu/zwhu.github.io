SessionEntry 如何变化

原始记录不会被删除。 新增的 CompactionEntry 只决定下一次构造模型上下文时，哪些历史由摘要替代。

关键代码位置

阶段函数 / 类型位置职责
Token 计算与触发 estimateContextTokens
shouldCompact		 core/compaction/compaction.ts 优先使用最近一次有效 assistant usage；尾部消息按约 字符数 / 4 估算，并判断是否越过阈值。
寻找切点 findCutPoint
findTurnStartIndex		 core/compaction/compaction.ts 从后向前保留近期 token；不以 toolResult 作为切点，并识别单轮被拆分的情况。
准备与生成 prepareCompaction
compact		 core/compaction/compaction.ts 整理待摘要消息、上次摘要、文件操作；调用模型并合并 split-turn 摘要。
消息序列化 serializeConversation core/compaction/utils.ts 将消息转成带角色标签的纯文本；工具结果在摘要输入中最多保留约 2,000 字符。
记录与恢复 CompactionEntry
buildSessionContext		 core/session-manager.ts 保存 summary、firstKeptEntryId、tokensBefore，恢复为“摘要 + 近期原文”。
本项目持久化约束 pi_session_entries docs/architecture.md §7.3 / §8.2 / §8.3 / M3 Pi SessionEntry 作为 append-only 原始事实写入 PostgreSQL；投影可重建，不能修改或删除原始历史。
