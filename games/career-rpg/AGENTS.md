# 一路写来：像素 RPG

本文件适用于 `games/career-rpg/` 及其子目录，在仓库根目录 [AGENTS.md](../../AGENTS.md) 的基础上补充游戏规则。维护博客页面与发布产物时仍遵守对应目录和站点生成规范。

## 开始工作

- 先读 [handoff](./handoff.md) 确认当前阶段，再按任务读取 [规格](./spec.md) 与 [验收方案](./acceptance.md) 的相关章节。不要将设计提案当作已确认或已实现的功能。
- 当前处于美术设计阶段；先完善概念板与像素样品，按用户确认的阶段推进。
- 查看最新文件与 Git 差异，保留用户已有及无关修改。完成后更新 handoff 中的进度、验证证据和下一步。

## 项目边界

- 技术方向为 Three.js 加项目自用的简单引擎。引擎随南京样章的实际需要扩展，先不构建通用框架。
- 源码、素材、设计、测试和维护脚本集中于本子项目。只将明确列出的运行资源导出到 `docs/assets/career-rpg/`；源文件与产物位置见 handoff。
- 导出应可重复，提供同步检查；不手改发布资源，不导出概念稿、提示词、测试和工作文档。GitHub Pages 继续直接发布 `main /docs`。
- 游戏代码与资源仅在游戏页加载，不增加普通博客页面的游戏依赖请求。

## 美术与剧情

- 游戏画面使用用户指定的像素 RPG 风格，细节以规格中的美术方向为准；博客页面外壳沿用站点视觉规范。
- 区分概念板与生产素材。生产素材统一像素网格、调色板、帧尺寸和脚底锚点；保留源文件、生成提示词或工具记录以及外部素材许可。
- 真实经历以规格中的事实表与用户后续纠正为准，不编造事故根因、年份、真人外貌、原话或个人贡献。新补充同步更新规格，避免与验收方案矛盾。
- 剧情文字和状态分开维护，以稳定事件 ID 连接；使用 HTML/CSS 呈现对话与菜单，保持中文清晰和键盘可用。

## 实现与验证

- 验收先分责任，再分材料：Agent 完成当前阶段全部必验项并通过后，才能提交作者正式验收。图片与视频是审阅材料，不能代替技术检查；失败或未验证的必验项先自行解决。作者主要确认美术偏好、个人经历表达与体验，具体门禁见验收方案。
- 剧情状态可序列化，纯逻辑不依赖 DOM 或 Three.js；渲染不决定剧情。检查重复触发、跳过、读档、暂停和失焦时的状态一致性。
- 游戏循环避免每帧无谓计算与分配；管理场景资源释放。依赖固定版本并保留许可，体积和性能按验收方案实测。
- 发现问题先保留复现方式，修复后按需补回归测试、数据检查或可普遍检测的 lint 规则；保留解释真实陷阱的必要注释。
- 游戏检查实现后接入全仓 verify，不以文档中列出了检查代替实际执行。修改后从仓库根目录运行 `python3 scripts/verify.py`。
- 页面与交互改动另做桌面、移动端浏览器验证；真机性能不能用窄屏截图代替。PR 截图沿用仓库流程。
- 汇报区分自动检查、视觉审阅、实际交互和性能测量，未运行的项目明确标为未验证。不要以静态检查通过声称游戏可玩或性能达标。
