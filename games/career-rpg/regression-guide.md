# 试玩问题的回归与交付

依据[首批反馈](./review/2026-11-07-hefei-playtest.md)、[踩坑记录](./pitfalls.md)和[开发准则](./development-rules.md)，修复后重走同一套流程，并向作者交付逐分支截图报告。

## 两层检查

`python3 scripts/verify.py` 保留离线规则与发布同步检查，覆盖事件前置、合法快照、碰撞、收集及导出。它不能证明窗口实际隐藏、键盘能够连续操作或画面符合作者要求。

新增浏览器入口 `node games/career-rpg/web/tests/playtest-regression.mjs` 自动启动本地服务与隔离 Chrome，使用真实键盘事件走流程。主流程不用 Tab、脚本 focus、DOM click、剧情跳状态或预置存档；焦点专项用一次真实指针操作设置场景焦点，失焦专项真实切换标签页，二者单独标明。截图与报告默认在仓库外，避免反复提交录屏和图片。

## 命令与结果

修复后执行正式回归：

```sh
python3 scripts/verify.py
node games/career-rpg/web/tests/playtest-regression.mjs --mode=acceptance
node games/career-rpg/web/tests/nanjing-playtest.mjs --out=/仓库外/新的南京报告目录
node games/career-rpg/web/tests/shared-playtest.mjs --out=/仓库外/新的共用章节报告目录
```

正式模式按新需求验证，不回退到已经要求删除的接任务/学习确认步骤；前置分支缺失时记录失败及后续未执行项。只有全部选定案例通过，浏览器命令才返回 0。某个问题需定点复现时可用：

```sh
node games/career-rpg/web/tests/playtest-regression.mjs --case=dialogue-focus
node games/career-rpg/web/tests/playtest-regression.mjs --case=automatic-resume
node games/career-rpg/web/tests/playtest-regression.mjs --case=restore-dialogue
```

需要为旧版本保留失败证据时使用：

```sh
node games/career-rpg/web/tests/playtest-regression.mjs --mode=baseline
```

baseline 允许明确记录使用旧按钮继续取证，仍按新要求报告失败，不作为验收通过。可以加 `--out=/绝对路径/新的报告目录` 保存到指定位置；目录必须位于仓库外，已有报告不会被覆盖。Chrome 可用 `CHROME` 指定路径，默认识别本机 macOS Chrome 或 `google-chrome-stable`。

## 主流程与分支

| 范围 | 分支与截图 | 主要验证 |
| --- | --- | --- |
| 开场 | 面试名牌、完整文案、Enter 收起；场景获得焦点后再 Enter | 文案正确，逻辑与实际可见性一致 |
| 可选交互 | 两位同事、面试前书架 | 仅阅读，不提前接取需求或获得技能 |
| 老板对话 | 争取机会、玩家回应、老板同意、按住 Enter | 方向键与确认可用，一次按下不连续跨页 |
| 需求入口 | 继续探索、重新打开、确定开始 | 两种选择都存在；取消不接取，确定只迁移一次，无空对话 |
| 白天学习 | Linux→jQuery、jQuery→Linux | 交互可达，无多余 Linux 说明；书籍提示正确，获得弹窗可确认 |
| 夜间学习 | Java→数据库、数据库→Java；与白天顺序组成四条完整路径 | 日夜转场、前置条件、四项收集结果一致 |
| 道具绘制 | 白天、夜间、收集完成 | 记录当次绘制到主画布的道具图及透明度，附截图核对电脑和书架 |
| 章末与手册 | 加薪、完成、手册、刷新、取消重玩、确认重玩 | 进度可恢复，取消不清数据，确认回到新开局 |
| 状态恢复 | 移动后刷新、对话及选择中刷新、按住移动键切走再回来 | 保持可恢复状态，无暂停弹窗和残留按键 |
| 共用界面 | acceptance 检查南京、杭州开场；shared-playtest 从新开局走到各自章末、手册与刷新 | 南京论坛、CTO、自己电脑查日志、复盘与章末可达；杭州报到、五项技能、五张单及白板点亮；不冒充美术、性能或真机验收 |

四条完整合肥路径分别从全新 Chrome profile 开始，不种检查点。复现工具出错、行走未到目标或上游需求未实现时，记录阻塞位置和截图，不将后面的步骤记成通过。旧 UI 迁移专项以真实键盘到达 asked 状态，再只替换存档中的旧对话页元数据，剧情和位置保持原值；此夹具单独标明，不用于推进主流程。每条合肥路径在选择主角回应后明确检查下一句是老板答复，不能仅以最终进入需求阶段判通过。字号、按钮观感和家具造型仍需实际审阅截图，自动检查只记录字号及相关状态，不代作者确认视觉偏好。

## 截图报告

每次运行输出 `report.md`、`result.json` 和对应 PNG。报告逐案例列出操作范围、通过/失败、反馈编号、实际正文与按钮、游戏状态、窗口实际可见性、焦点、字号和截图；失败保留现场与阻塞原因。JSON 另存源码 hash、请求状态、按键请求及浏览器采集的输入片段，便于复核。

对话可见性同时检查布局、computed style 与 `hidden` 属性。世界道具检查观察实际画布绘制，而不以对象配置里存在或不存在 `icon` 字段代替画面。截图使用页面坐标，避免页面滚动后截错区域。刷新等待新 document ID；技能页保留确认前后画面，不能只交关闭后的空场景。

## 给作者的交付文档

修复后的交付以正式模式报告为附件，正文按以下内容整理：

1. 本次修复版本、访问地址、测试环境和覆盖范围。
2. F01～F14 的问题编号、原因、修改、验证结果及截图位置。
3. 每个实际执行分支的截图；缺失、失败或未验证的分支明确列出。
4. 离线检查、真实交互与视觉审阅分别给出结论，列出剩余问题。
5. 用户复验后的反馈补回原问题编号；游戏 PR 等作者说「合」后合并。

文档和截图交付前先由开发者核对，不用报告生成成功代替回归通过。修复范围改变时更新这份分支表；源码已变动就重新生成对应报告，不复用旧版截图充当新版本证据。

## 南京正式回归

`nanjing-playtest.mjs` 检查作者 N01～N21：四个主线动作、指定正文、删除菜单、三位 NPC 和主角坐姿、椅旁站位、显示器碰撞、实际闪点、四项可选收集、获得页刷新/取消重玩、手册与章末、南京→杭州。另一条全新存档不收集技能，直接完成本章。

旧存档部分单独标为夹具：遍历18种旧合法进度，注入已删除的旧对话和落在新碰撞中的位置，刷新后保留旧 flags 并实际操作到完成。报告同时存迁移后的页面和完成截图。旧清单仍保留在纯剧情 API，供存档兼容；当前界面不暴露这些任务。剧情核心 schema 和存档键不变，UI 版本为 `play.chapterUI=2`。


南京修复完成后的具体命令可按范围执行：

```sh
node games/career-rpg/web/tests/nanjing-playtest.mjs --case=main --out=/仓库外/新的南京主线目录
node games/career-rpg/web/tests/nanjing-playtest.mjs --case=legacy --out=/仓库外/新的南京旧存档目录
```

`--case=seating` 专门核对主角臀部高度和椅背不能遮头；`--legacy-index=N` 只复验指定旧进度。全量默认包含主线与18种迁移。旧终态迁移和完成使用不同截图名，避免同名覆盖。正式结果与作者逐项反馈见[南京修复交付](./review/2026-11-08-nanjing-fixes.md)。
