# 《一路写来》当前技术方案

定稿日期：2026-11-05。依据用户本轮决定更新制作路线；本文件规定后续做法，不表示相关工具链已实现。与当前规格、美术规范或旧交接冲突时，以本轮决定为准；历史事实与验收证据保持原记录。

## 交付范围

当前面向桌面键盘游玩，使用已有本地浏览器入口开发和预览。H5 发布、移动端、触控、弱网交付和博客上线暂不实施；桌面原生安装包及封装工具尚未选择。暂不考虑 H5 不等于重写已有浏览器实现，也不意味着已经交付桌面安装包。

既有南京主线、四向行走、NPC、表情、打字坐姿和头部气泡继续复用。先补当前场景缺口并验收，再制作下一场景；用户随后授权先集中准备剩余场景缺失人物设定；这不授权重画已有南京或恢复全部旅程。loop 与 TraeX 后台工作保持暂停，单次任务须有明确授权。走路卡顿仍未解决，其排查继续暂停。

## 渲染与逻辑

保留 Three.js 0.180.0、本地依赖和 MIT 许可。采用固定正交相机，显示二维背景、物件与人物图集；本轮不引入全三维人物、实时建模或新引擎。程序生成的 PNG 与 image_gen 输出的 PNG 使用相同加载路径。

输入、固定步长更新、碰撞、交互、暂停与资源释放由项目自用的简单引擎管理。剧情使用独立可序列化状态及稳定事件 ID；存档只保存游戏自己的稳定检查点。中文文本、头部气泡和菜单保留 HTML/CSS，全流程键盘操作及防跨界面误触要求不变。

现有逻辑空间为384×216，站姿高42～44、坐姿高40逻辑像素；这些是现有运行参数，不是要求 image_gen 直接生成的图片尺寸。新图集的像素尺寸、帧排列、显示高度与脚底锚点须一起登记，再通过同场景预览确定。16×24、48×64人物及16×16地砖均不作为强制标准。

## 美术制作分工

| 内容 | 默认制作方式 | 关键检查 |
| --- | --- | --- |
| 主角、NPC、表情、行走与关键姿态 | image_gen 参考现有南京对应素材生成；已有可用素材优先复用 | 同一人物的脸、发型、头身比、衣色、四向与动作一致，不能只验单帧美观 |
| 地板、墙面、桌椅、电脑等可复用环境物件 | 程序描述像素轮廓、图层、配色与布局，导出PNG或图集 | 与南京成品同视角、尺度、描边及细节密度；不使用通用方块代替成品 |
| 独特场景、标志物与复杂环境细节 | 用户最新要求全部用程序组合绘制，不调用image_gen；人物/表情路线不变 | 先核对真实经历和空间依据，避免办公室换色凑场景 |
| 裁切、锚点、图集排布、压缩及统计 | 可重复执行的本地处理脚本 | 不覆盖原图，记录处理参数并复核输出 |

Codex 负责人物/表情的 image_gen 调用、参考输入和最终视觉复核。TraeX 可在获授权后编写环境绘图、素材处理及游戏代码，并完成自检；没有内置 image_gen 时提交具体素材请求，由 Codex 生成。人物纯程序绘制保留为实验路线，不作为默认生产方式。程序工位和两份四向人物样品均未获正式替换认可。

## 原图到运行素材

1. **复用与参考**：先查已有素材，确认确实缺失时才生成。实际给 image_gen 传入南京参考图片，说明保持项、变化项、方向/动作与用途；不只在提示词里写风格名。
2. **保存原图**：原始输出、提示词、参考文件、工具及版本记录留存。新素材可放在 `art/source/<素材ID>/`；旧图维持原路径，不为目录统一移动或覆盖。原图中的来源信息保留在归档中。
3. **生成候选**：处理脚本、参数和候选输出放在 `art/processed/<素材ID>/`。先做裁切透明留白、切帧、排布及锚点校准；裁切偏移要计入帧元数据，防止动画抖动或坐姿错位。
4. **压缩**：使用本地脚本优先比较无损PNG与无损WebP候选。逐像素无损要求尺寸及解码RGBA相同，并检查色彩解释和透明边缘；文件元数据的变化另行记录。
5. **必要的有损处理**：缩放、调色板量化、抖动或其他有损编码会改变画面，须作为独立候选保存。用近邻缩放审阅像素图，禁用柔化插值；默认避免抖动噪点。与原图及南京实机同尺度对照，检查脸、发型、描边、衣色与动作。没有满意结果就保留较大版本，不承诺压缩比例。
6. **验收与接入**：记录尺寸、帧数、调色板/alpha、锚点、原始/输出SHA256、文件字节和处理命令。Agent先做视觉与实际渲染复核，作者确认涉及造型取舍的候选后，才接入 `web/art/` 并更新配置。原图、候选、审阅截图不混入运行依赖。

PNG字节、解码RGBA大小及GPU资源分别统计；缩小文件不自动证明运行内存减少。PNG运行版可先沿用现有加载器；采用WebP或其他格式前单独验证当前桌面环境的解码、色彩、透明与实际显示。格式转换不要求切换引擎。

## 地图与场景组织

采用人物图集、可复用物件、独特背景/前景和独立碰撞/事件数据组合的方式。重复地面与墙可以用图块，桌椅可自由摆放；场景特有构图可保留整图或专门绘制的局部。当前南京背景继续保留，不立即拆成图块重制。

角色以脚底定位并按Y排序；家具分清可碰撞脚印和需遮挡人物的前景，不把整张透明图的矩形都视为障碍。图像、碰撞、交互点和坐姿锚点来源于同一份场景配置。后续扩展逐个场景验证。

## 当前验收与交付

当期检查为桌面键盘流程、剧情与存档、视觉一致性、素材处理记录、实际渲染和受影响的回归。南京的部分键盘/阅读/回退检查已有独立证据，完整场景尚未通过；生命周期只确认20轮可观测计数与显式释放，不扩大为完整内存通过。

此前512 KiB gzip、2 MiB原始、1 Mbps/150ms下8秒，以及4 MiB/6 MiB/40秒候选，均属于H5加载路线记录。H5暂不实施后，这些网络指标暂停作为当前阶段的阻塞项；历史失败仍保留，不改写为通过。停止冷启动候选任务，不批准40秒目标。当前持续记录运行包、图像解码大小和桌面资源使用；新的数值上限需基于后续实际目标设备确定。

桌面操作流畅、资源正确释放和质量优先仍是要求，暂停卡顿排查不等于该问题通过。移动端/真机手机、触控、弱网及线上部署只在恢复对应阶段后验收，不要求用模拟窄屏代替真机。博客原有验证与隔离约束保留。

本轮更新方案并按用户追加授权准备7个缺失人物的四向/表情设定；清单见 `art/character-roster.md`。原图与透明边缘/压缩候选独立保存，未替换生产素材，不执行性能实验或发布。下一步核对人物设定，再切分、校准和审阅运行图集；已有主角和南京同伴继续复用。
