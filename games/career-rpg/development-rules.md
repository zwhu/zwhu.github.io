# 《像素前端》开发准则

依据[踩坑记录](./pitfalls.md)和作者已确认的要求维护。每条准则写清执行动作与适用范围；新问题查明原因后，再补充对应准则，避免为同一原因反复增加相似条目。

2026-11-07 的[首批试玩反馈](./review/2026-11-07-hefei-playtest.md)是当前修复依据。取消暂停弹窗、统一对话键盘控制和精简确认步骤的要求覆盖旧文档中冲突的方案；本批已修复并通过本地回归，见[修复交付](./review/2026-11-08-hefei-fixes.md)。

回归命令、主流程分支与逐分支截图交付见[验证与交付](./regression-guide.md)。

## RULE-01：分别配置世界外观与交互内容

接入物件前检查背景是否已画有电脑、书架、桌面或白板。交互热区、闪点、对话卡片和世界绘制分别确定，不能因为存在一张 `icon` 就把它画到世界中。去掉重复图片时保留事件和收集条件；需要状态变化的白板在原位置切换。人物与家具同时存在时，检查椅背、桌面等前景的遮挡顺序，并区分坐姿的脚底/臀部锚点；碰撞范围要贴合可见家具。学习事件、收集入口和闪点必须指向同一实际物件，不能留下通道上的虚拟入口。移除图标时检查尚未学习的入口仍有提示；同一家具上的学习点共用闪点，不叠出新物件。依据：BUG-001。

## RULE-02：从用户现象追查原因

收到反馈先保留原话，再记录实际表现、期望表现和可用的复现信息。复现和代码检查由开发者补齐，不把整理完整报告的工作交给用户。原因未查明时写「待定位」，提出假设时写出支持证据及验证方法。不能把偏好问题改写成技术故障，也不能把猜测写成已确认原因。

## RULE-03：按同一流程验证修复

保存问题发生的版本和操作顺序，在修复版本重走这条路径。视觉问题看实际游戏画面，交互问题使用真实按键推进；检查剧情结果、收集、失焦恢复和存档中受影响的部分。自动检查通过只能说明其覆盖范围，不能据此关闭尚未实际验证的问题。截图、日志与所验代码版本必须对应。

## RULE-04：共用逻辑修改检查所有使用章节

修改输入、绘制、对话、技能收集或存档的共用代码前列出受影响章节。对每章执行相关流程，既确认问题消失，也确认原事件仍可到达；为可稳定复现的逻辑缺陷补必要的回归检查。单章通过不能代替三章共用逻辑的验证。依据：BUG-001。

## RULE-05：把用户反馈落实到记录与规则

每轮收到问题后更新踩坑记录的状态、原因、方案和验证证据。重复反馈归入已有编号；不同原因分别记录。修复后把适用的预防动作写入本文件，并在问题条目中引用其编号。规则不得扩大为用户未授权的重画、剧情改写或新场景制作。

## RULE-06：长任务前保存可接续的成果

从最新主分支开独立分支，保留已有及无关修改。形成可说明的改动后保存提交并推送分支，再继续长时间录制、截图或验证。PR 与交接写明已完成、失败或未验证项、证据和唯一下一步；中断后另一位开发者应能从仓库接续。提交和开 PR 不代表验收通过，游戏改动仍等待作者说「合」后合并。依据：DEV-001。

## RULE-07：以当前代码和交接确认状态

开始任务时核对本地与远端版本，读取 handoff 顶部当前恢复点。实现、验证、发布和待办分别记录；资料与代码矛盾时检查实际加载路径和提交，不用旧设计推断现状。更新代码不等于修复已有问题，历史截图也不自动覆盖新版本。

## RULE-08：说明验证范围后再关闭问题

交付时分别说明自动检查、实际交互、视觉审阅与性能测量的结果，注明未验证项。涉及作者美术偏好、真实经历或最终体验的条目，在开发者验证后提交作者确认。作者的新反馈继续补在原问题下，不以既有测试通过代替处理反馈。

## RULE-09：当前对话接管方向键与 Enter

进入对话即选中第一个可用选项，用方向键切换，Enter 确认；不能要求先用鼠标点击或 Tab 聚焦按钮。有选项时按选择执行，无选项时 Enter 推进下一句，末句后收起对话。所有对话、确认页和技能获得提示共用该机制，并以可见选择标记对应当前动作。对话期间角色不移动；一次按下不能跨新页面连点。隐藏按钮、正文焦点或焦点恢复都不得让当前对话失去确认入口。依据：BUG-002、BUG-006。

## RULE-10：自动保存和恢复状态，不弹暂停菜单

移除「稍作停留」与手动恢复步骤。自动保存章节、事件、位置、朝向、收集及当前对话等可恢复状态；用稳定 ID 记录，不序列化函数、DOM、图形资源或按键。失焦时清输入并停止后台更新，返回后自动接续；刷新和重开也应保持进度与操作上下文。变更存档格式时兼容旧数据，保留损坏存档和写入失败的处理，不要求每帧同步写入 localStorage。依据：作者 F05、BUG-004。

## RULE-11：文字有字号上限，按钮遵循同一规范

对话正文、名牌和按钮分别确定字号、层级与上下限，不把场景缩放比例无上限套到文字上。先用真实桌面画面检查长中文、换行、间距与遮挡，再确认具体数值；作者未指定字号时，不将建议值写为已确认。普通选项、继续、确定与技能弹窗共用按钮视觉、选中和确认行为，不单独给「OK」另设交互分支。依据：BUG-003。

## RULE-12：对白和确认步骤按作者意图设计

保留作者指定的文案与改前内容；技术名拼写按正确名称统一，并保留反馈原话。选项已经表达玩家台词时，确认后进入对方回应，不再重复展示同句并要求继续。目标条负责指路，对话负责剧情；事件完成后不要再把同句目标作为对白。记录、查看、确认不能凑成无意义的前置任务，跨章节过场必须处于正确顺序。每个确认按钮应对应实际选择或必要状态变化，不能连续出现重复接任务、读说明、再点确认等无新增作用的步骤。精简页面时同时处理事件前置、合法存档和收集条件，不能只删按钮；从玩家完整路径验证结果。事实和表达以作者补充为准，不扩大为重写其他技能或经历。依据：BUG-005、BUG-006、BUG-007。

## RULE-13：回归检查实际呈现，不只检查状态属性

窗口收起必须核对 computed style、布局可见性与游戏状态，不能只断言 `hidden=true`。绘制问题观察真实画布和截图，配置字段不代替实际画面。每个主流程分支保留操作与截图；上游失败或工具出错时标明未执行部分，不能用种快照、脚本点击或旧按钮回退冒充新流程通过。刷新先确认新页面已加载，再核对恢复状态，防止误读旧页面。截图工具等待游戏加载完成，技能页保留确认前后画面。源码和截图版本对应，报告生成后实际审阅，再交付作者。技能检查同时核对玩家可见的解锁条件、获取地点和操作提示，区分未解锁、可领取与已获得；不能由脚本掌握坐标/role后成功收集，就认定玩家能够发现入口。依据：BUG-002 的隐藏样式覆盖、BUG-013 与本批回归要求。

南京本批依据和已确认主线见[南京反馈](./review/2026-11-08-nanjing-playtest.md)与[主线核对方案](./nanjing-flow-proposal.md)。作者已确认日志工位、复盘和章末安排，按方案实施；新反馈继续记录。


## RULE-14：界面简化必须兼容每种旧进度

删除前置任务时，列出所有旧合法 flags 组合，并逐个验证接续到章末。保留章节键、技能 ID 和已有完成标记；用 UI 版本重建已删除的旧菜单。家具碰撞范围扩大后，旧位置移到最近可走点，不清空剧情。过场确认必须实际进入目标章节，并恢复该章已有存档。主流程使用全新存档和真实键盘；旧存档夹具单独标明，不能用它代替主流程。依据：BUG-010、BUG-012。

## RULE-15：场景配置必须进入实际渲染链

家具前景、深度和裁切配置要传给渲染器，在真实画布记录绘制顺序并审阅截图；只添加配置字段不算完成。坐姿分别检查主角臀部锚点和 NPC 脚底锚点，椅背应遮住坐姿下半身，站立交谈点放在椅旁。采集脚本彼此隔离作用域，确认记录非空且无浏览器异常，避免把取证工具错误当游戏失败。依据：BUG-008、BUG-009。
