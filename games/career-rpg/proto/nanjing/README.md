# 像素前端 · 重做 · 南京可玩原型（v0.4）

## 目标
和合肥一样，先用方块和文字验证：玩 5 分钟，想不想再来一局。
南京要玩出的感觉：第一次做 C 端，上线是一场赌，炸了要会救，救完要会复盘。

## 一句话玩法
在南京，你是一家 BBS 论坛小公司的全栈工程师。公司只有 3 个创始人和 4 个新人，你是新人之一；没有产品经理，也没有测试。一个版本周期 4 周，每周 5 天，每天 3 个行动点。
要把功能做完、上线，把论坛日活做上去，同时别让线上炸了。第 4 周会撞上一次大事故：首页登不上。

## 和合肥相同的部分
- 行动点、体力、熬夜都沿用合肥规则；Dota 小游戏沿用合肥那版。
- 需求单有期限，延期扣分。
- 同一个随机种子能复现同一局。

## 和合肥不同的部分
### 指标：日活和口碑
- 日活：功能上线后才涨，做完不上线不算。
- 口碑：0–100，开局 50。事故扣口碑，口碑低于 20 时日活开始掉。
- 每周五看两条线：日活到本周目标，口碑不低于 30。任一没过记一次「创始人约谈」，约谈两次本局结束。

### 两步走：做完 → 上线
- 需求单做完后进入「待上线」，要再花 1 个行动点上线。
- 每次上线有事故概率（初始 30%）。写过测试的单子降到 15%；会灰度时只先放一小部分用户，出事损失减半。
- 可以选择攒几张一起上线，省行动点，但出事时一起炸。

### 需求单（论坛业务，全栈）
- 前台：发帖、回帖、楼层分页、帖子搜索、签到、个人主页。
- 后台：版主后台、防灌水、敏感词过滤、消息通知。
- 数据：热帖排行、备份数据库。

### 事故
- 普通事故：上线后随机触发，例如「回帖 500」「帖子乱码」「灌水机器人刷屏」。期限 1 天，要先「定位」再「修复」，各 1 个行动点；会回滚时可以直接回滚，1 个行动点止血。
- 事故不处理：每天扣口碑。

### Boss 关：首页登不上（第 4 周固定触发）
- 第 4 周周二，首页登录全挂，口碑每过 1 个行动点扣 5。
- 排查是一串选择：看监控、查日志、看最近上线、查数据库连接、回滚、改配置。只有一条路对，走错一步多花 1 个行动点。
- 学过「观测」直接排除一半错误选项；会回滚时可以先止血，再慢慢查。
- 处理完必须做一次「复盘」（1 个行动点），才能拿到「从失败中学习」。

## 技能（南京 5 个，学了就有用）
- fibjs / Node.js 全栈：前后台各类单子少 1 点。
- 集成测试（CI/CD）：给单子补测试，上线事故概率减半。
- 敬畏上线（灰度、观测、回滚）：解锁灰度上线和一键回滚，Boss 关排查少一半选项。
- 从失败中学习：只能在事故复盘后获得；之后同类事故不再发生。
- React / Webpack（章末钩子）：第 4 周起才能学，学会后结局多一句引出下一章「去阿里」。

## 能互动的人（v0.4：公司只有 3 个创始人和 4 个新人，没有产品经理和测试）
- 和合肥同一套：点小人，画面底部弹米色对话窗；不花行动点，每人每天一次，说法每天不同。
- 催上线的创始人：催你提前上线。答应了这张单马上上线、日活多涨一截，但事故概率 +15%。（原「产品经理」的规则原样搬过来。）
- 管事的创始人：周五约谈；Boss 关时会站在你身后问「好了没」，不影响数值，只是压力。（原「老板」。）
- 论坛老用户（版主）：在帖子里反馈「回帖好慢」「登录有点卡」，是事故要来的预兆，也是 Boss 关「首页登不上」的前一天提示。
- 没有测试同事：测试只能自己补。不学也能给单子补测试；学了「集成测试」后事故概率再减半。
- Boss 关排查时，「看老用户的帖子」也是一条排查选项，看对了能少走一步。
- 第三位创始人和另外三个新人这版不做互动。
- 验收加一条：三个人都能点，每人说法不同；答应催上线的创始人后事故概率的变化，在界面上能看到。

## 胜负
- 失败：被创始人约谈两次，本局结束，显示原因和数据。
- 胜利：撑过 4 周。结局分两档：
  - Boss 关处理好、做过复盘，且第 4 周结束时口碑不低于 34：「扛住了，也学会了怎么扛」。
  - 勉强撑过：「论坛还活着，你也还在」。
- 学了 React / Webpack 的，结局后接「去杭州」过场。

## 数值（v0.3 定稿，按 240 局×3 种打法调过）
- 每天早上新到 1 张需求单，期限 4–6 天，难度从 1、1、2、2、3 里抽。
- 上线增加的日活 = 8 + 难度 × 4。答应催上线的创始人时，这张单日活再加一半。
- 第 1–4 周日活目标：30、64、110、160。
- 需求单延期扣口碑 4；上线炸了当场扣 3；事故未处理每天扣 3，灰度时每天扣 2。
- 口碑低于 20 时，当天日活掉两成。
- 首页登不上，夜里还没止血再扣口碑 6。
- 学技能的行动点：fibjs / Node.js 2 点，集成测试 2 点，敬畏上线 3 点，React / Webpack 3 点（第 4 周起可学）。
- 事故概率最高记到 90%。
- 目标（已达到）：只做最急的单过关 40–60%；有规划的打法过关 70–85%、好结局 40–60%；乱点过关不超过 15%、好结局不超过 3%。

## 必须有的玩家决定（检查好玩的标准）
1. 这张单子补不补测试再上（多花点 vs 少冒险）？
2. 攒着一起上，还是做一张上一张？
3. 事故来了，先回滚止血，还是直接查到底？
如果试玩下来这三件事都不需要想，就说明规则还不对。

## 不做
像素图、剧情对白、和合肥的过场衔接（等合肥完整版定了再接）。

## 验收（真实运行，不认截图 demo）
- 预览链接能从开局玩到胜利或失败，不卡死、不报错。
- 同一个种子能复现同一局。
- 上线事故概率在有测试、有灰度时的变化，界面上能看到数字。
- Boss 关第 4 周周二必定触发；走对和走错的路径都有录屏。
- 至少一段失败录屏、两档胜利各一段录屏。
- 用户本人玩一局以上，回答「还想再玩吗」。

## 交接
- 规则定稿后交给工程负责人：放在 games/career-rpg/proto/ 下，和合肥共用引擎，从 main 开新分支，先 push，开 PR 不合。
- 额度快没时先留 2–3 美元做交接和提交。

## 操作
点场景里的东西，人会走过去，走到了才触发。走路不花行动点，也不花体力。

- 催上线的创始人、管事的创始人、版主：走到旁边，再打开原来的对话。
- 第三位创始人、费翔、米色新人、新人 4：可以走过去。这版没有对话。
- 自己工位的电脑：走回座位坐下，需求单进入画面。干活仍用原来的按钮。
- 书架在画面右边。走过去以后，学习卡进入画面。学习仍用原来的「学」。
- 点空地只走动。
- 休息、打 Dota、睡觉仍是底部按钮，不必走过去。
- 首页登不上的排查，和夜里的事故，仍用原来的按钮，不靠走路触发。
