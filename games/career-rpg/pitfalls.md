## 记录方式

每个问题使用稳定编号。保留用户原话，补充章节、地址、版本、操作顺序、实际表现和期望表现；信息不足时先记录，不要求用户一次填写完整。

原因分为「已定位」「推测」「待定位」。已定位的原因必须附代码、日志或复现证据；用户描述了现象，不代表技术原因已确认。修复方案与已完成修改分别记录，修复后补同一操作顺序的验证结果。

状态依次为：待复现 → 已复现 → 待修复 → 待复验 → 已解决。无法复现时保留记录及测试条件。只有修复和相应验证完成后，才能标为已解决；美术偏好、经历表达和最终体验仍由作者确认。

## BUG-001：道具图叠在已有家具上

**来源与版本**：2026-11-06 的[交接](./handoff.md)，以及 2026-11-07 首批反馈 F06、F13、F14（截图 #4、#11、#12）。本轮核对本地 `main` 的 `3d5184c`；作者提供了叠图截图，Agent 未做独立浏览器复现。

**问题与期望**：合肥自己的工位已有电脑，Linux 图标又叠出一块屏；左侧书架出现显示器与气泡图；夜里 Java 和数据库图叠在同一工位，并以半透明显示。杭州的 Webpack、设计模式和需求单也有额外叠图。玩家希望直接交互背景中已有的电脑、书架、桌面和白板，保留闪点、E 键、对话卡片及手册收集。

**复现路径**：合肥面试结束后查看自己的工位和左侧书架，再推进到夜间学习；杭州依次查看 Webpack 工位、设计模式学习点、五张需求单和白板。南京需实机检查论坛电脑、书架和排查电脑，现有交接未确认南京存在同类叠图。

**为什么会这样（代码已定位）**：[main.mjs](./web/main.mjs) 用 `objects.filter(o => o.icon)` 决定哪些对象加载图片，并全部加入 `propViews` 绘到世界中。`icon` 同时承担道具展示与世界绘制的用途，而房间背景已经画有家具。`nightDim` 在夜间将图片透明度设为 `0.45`，不能消除重复形状。合肥与杭州的具体配置分别见 [hefei.mjs](./web/chapters/hefei.mjs) 和 [hangzhou.mjs](./web/chapters/hangzhou.mjs)。

**怎么改（待实施）**：明确区分世界绘制、交互热区、闪点和对话卡片。移除重复的世界道具图，保留原事件和学习点；杭州白板须贴合原白板位置切换明暗状态。不能直接删除交互对象，或只用透明度掩盖重复图形。

**修复后怎么验**：实际运行合肥白天和夜间，确认工位只有一台电脑、书架只有书；四个技能仍可获得，面试阶段的书架拦截文案仍正确。杭州完成报到、学习、收集五张单和白板点亮，确认五个技能可收集。南京核对无重复道具图。三章对话窗、坐姿、行走和原剧情保持正确，附对应版本截图。

**后续怎么避免**：执行 RULE-01、RULE-03、RULE-04。每个物件接入前先确认背景是否已经包含其外观，再决定是否需要独立绘制；修改共用绘制路径时检查三章的实际表现与事件可达性。

## BUG-002：对话和技能弹窗不能按统一键盘规则推进

**问题**：F01 的进门对话无法关闭，F03 的老板对话不能直接回车执行下一步，F10/F12 的技能弹窗「OK」无法正常确认。点击与回车需分别复验，不能只凭静态截图断定同一失效原因。

**为什么会这样（部分已定位）**：[main.mjs](./web/main.mjs) 的 `keydown` 只有在 `document.activeElement` 位于 `.choices button` 时才处理方向键与 Enter。纯文字页通过独立的 `continue-caret` 按钮收起，缺少按当前对话状态处理 Enter 的统一入口；正文取得焦点时，方向键又进入文字滚动分支。`show()` 虽然尝试聚焦首个选项，这一设计仍依赖 DOM 焦点正确恢复。`closeConversation()` 在 `dismissible=false` 时转入暂停，技能获得页还单独拦截 Esc。具体哪条路径让本批按钮失效、鼠标点击是否同样失败，仍需真实键盘和指针事件复现。

**本地已复现的两个原因**：`--case=dialogue-focus` 用真实指针使场景获得焦点后按 Enter，仍停在 dialogue。正常开场 Enter 则进入 explore，并设置对话 `hidden=true`，但 computed style 仍为 `display:flex`，窗口和旧按钮继续可见；截图已实际审阅。[style.css](./web/style.css) 中较后的 `.speech-bubble.docked` 与较早的 `.speech-bubble[hidden]` 优先级相同，前者的 `display:flex` 覆盖隐藏样式。原检查若只读 `hidden` 属性，会把这个场景误判为关闭成功。技能页的 Enter 也能结束逻辑流程却留下窗口，基线回归已捕获；任意环境下的鼠标点击仍需单独验证。

**怎么改（待实施）**：将方向键和 Enter 路由到当前活跃对话，进入对话即选中第一个可用选项，无需先用鼠标或 Tab 获得按钮焦点；有选项时 Enter 执行当前选择，无选项时推进下一句，最后一句后收起。普通对话、技能获得、手册和确认页共用选择与确认机制，保留可见选择状态及按下/释放隔离。不得把按住一次 Enter 当作多次确认，也不能通过收起文字跳过未确认事件。

**怎么验与避免**：按 F01/F03/F10/F12 的流程，仅用方向键和 Enter 从新开局走到章末；另核对指针确认、对话收起和焦点恢复。检查一次确认后不会触发下一页按钮或移动角色。执行 RULE-03、RULE-09；旧版本键盘检查不能自动覆盖新对话布局。

复现与回归命令、分支和截图报告见[验证与交付](./regression-guide.md)。本地已运行的定点检查为 dialogue-focus、opening-and-resume、automatic-resume，均按新要求失败；游戏源码尚未修复。基线全流程中的旧按钮操作单独标明，失败的检查不会因流程最终走通而改为通过。

## BUG-003：场景放大后对话字体与按钮过大

**问题**：F04 指出字体过大，F10/F12 要求按钮的样式和行为统一。

**为什么会这样（样式已定位）**：[style.css](./web/style.css) 的 docked 对话使用 `--u: calc(100cqi / 384)`，正文、名牌、按钮字号均为 `calc(11 * var(--u))`，因此随游戏区域宽度放大。普通菜单按钮另用固定字号、圆角及边框，继续箭头又有单独的外观与焦点样式。这里既有作者的字号偏好，也有多个界面的规范差异，不能只称为排版计算错误。

**怎么改与怎么验（待实施）**：为正文、名牌和按钮设置清晰层级及字号上下限，缩小当前对话文字；共用按钮的选择、确认和返回样式，技能弹窗的「OK」纳入同一套中文动作规范。具体字号尚未由作者指定，需实际预览不同桌面宽度，检查长中文、换行、按钮间距、可见选择和遮挡情况，并提交作者确认。执行 RULE-09、RULE-11。

## BUG-004：暂停弹窗成为多余步骤，存档只覆盖章节进度

**问题与新要求**：F05 要取消「稍作停留」，将游玩状态保存到 localStorage。该要求覆盖旧文档中显示暂停菜单、点击继续的方案。

**为什么会这样（代码已定位）**：[index.html](./web/index.html) 定义了 `pause-menu`；[main.mjs](./web/main.mjs) 在 Esc、窗口失焦或页面隐藏时调用 `pause()`，显示模态窗口，并在部分对话中禁用手册和重玩。现有 [story.mjs](./web/story.mjs) 的快照只保存章节、状态、flags 和技能收集，不包含角色位置、朝向、当前对话页及选择；刷新用章节入口重新放置角色。因此已有 localStorage 并不等于可恢复完整游玩上下文。

**怎么改（待实施）**：移除暂停弹窗与相应交互步骤，自动保存章节、角色位置/朝向、已确认事件、技能收集、当前对话/选择及必要的界面状态。通过稳定 ID 和可序列化数据记录，不保存 DOM、函数、图形资源或按住的键。状态变化和离开页面时保存；失焦仍清输入并停止后台更新，回来自动恢复，不要求点「继续」。保持旧存档兼容、损坏存档保留及写入失败提示。

**怎么验与避免**：在开场、选项、学习、技能获得和日夜转场前后刷新及重开，核对位置、剧情与收集一致；切走再回来不弹暂停菜单，不遗留移动按键或重复确认。执行 RULE-10，不将存档设计缩减为“某个章节完成了几个事件”。

## BUG-005：开场文案缺少主动争取机会的转折

**问题与作者文案**：F02 要补为「原本录用的人嫌工资低，没来。我鼓起勇气，毛遂自荐。」。

**为什么会这样（内容已核对）**：[chapter-hefei.json](./design/chapter-hefei.json) 的 `interview-narrator` 当前只有「原本录用的人嫌工资低，没来。」。新增后半句来自作者本批补充；之前未写入的制作原因没有证据，不代作者解释。

**怎么改与怎么验（待实施）**：更新此对白，名牌保留「面试」，核对新开局与恢复到面试阶段均呈现完整文案，其他老板对白保持其原要求。实现时同步事实依据与章节文案。执行 RULE-12。

## BUG-006：需求入口之后还重复接任务和确认学习说明

**问题与新要求**：F07 将自己工位入口改为「开始今天的需求」，选项为「确定」「继续探索办公室」；F08 删除后续独立「接任务」页；F09 删除截图 #7 中 Linux/Git 说明及「记下来」页。截图 #6 只有按钮、没有正文，也需作为空对话检查。

**为什么会这样（流程部分已定位）**：[chapter-hefei.json](./design/chapter-hefei.json) 的 H03 `take_day_task` 独立生成「接任务」和 `day_task_taken`，H04/H05 又以此 flag 为学习前置，并分别用「记下来」确认。技能随后还要通过收集与获得提示确认，操作被拆成多层。[main.mjs](./web/main.mjs) 在执行事件、展现对话、收集技能时分别处理这些界面。截图 #6 空正文的形成过程需再复现，不能直接归因为某个清空 DOM 的函数。

**怎么改（待实施）**：让入口的「确定」承接必要的需求状态变化；「继续探索办公室」收起入口且不接取需求。删除额外接任务和指定的 Linux/Git 说明确认页，保留学习、收集与日夜转场所需结果；同步前置条件、合法快照和旧存档兼容。只删除按钮而保留无人能触发的 `day_task_taken` 前置会卡住后续流程。

**怎么验与避免**：两种入口选择均可用键盘完成；之后学习和收集可达，Linux/Git 不再出现已删除的说明确认页，不产生空对话。从接取前后及旧保存进度恢复，仍可完成白天、夜间和加薪流程。执行 RULE-09、RULE-12，每个确认动作都须说明它改变了什么状态或表达了什么选择。

## DEV-001：修改只留在 VM，任务中断后没有交付

**来源**：[交接中的两轮失败记录](./handoff.md)。这些是历史交接材料，本轮未读取或复现已失效 VM 的日志。

**问题**：两轮去浮图任务都没有 commit、push、PR 和完整截图，后续无法从远端接续修改。交接记载第一轮在补截图时出错，第二轮卡在测试事件不被接受。

**为什么会这样**：已知修改未保存到可接续的仓库分支，任务随后中断，导致制作结果未交付。两次异常的具体技术根因尚未定位，不能仅凭交接推断为额度耗尽、工具故障或剧情实现错误。

**怎么改**：下一次从最新主分支开独立分支。形成可说明的改动后保存提交，推送分支并建立 PR，再继续耗时的截图和验证；未通过的检查明确列出，保留失败日志、复现命令和唯一下一步。游戏改动仍等作者明确说「合」后合并。

**后续怎么避免**：执行 RULE-06。检查失败时，必须能在仓库分支和交接中找到已完成的改动及剩余工作，不能只留一句「VM 里改好了」。
