# 《一路写来》规格草案

更新：2026-11-05。南京 Web 样章已实现，当前升级共用场景表现；其余旅程仍在设计。未确认的名称、数值和视觉参数保持提案状态，不将技术检查当作作者认可。

## 目标与范围

### 全键盘操作目标

所有场景的核心流程均可仅用键盘完成，无须鼠标：移动、选择邻近交互对象、接取任务、推进和关闭对话、选择分支、查看及关闭手册、暂停和继续、重玩，以及存档异常提示中的操作。方向键/WASD移动，E/Enter交互，Q切换邻近对象；菜单和选项支持Tab/Shift+Tab切换焦点、Enter/Space确认、Esc返回或关闭。快捷键在界面提示，焦点清晰可见，弹层关闭后恢复到合理位置；文本或菜单获得焦点时不能误触角色移动。最终按实际界面维护统一按键表，不将“能键盘走路”等同于全键盘完成游戏。

访客通过合肥、南京、杭州的像素 RPG 旅程认识作者。主线是经历改变做事方法：主动争取机会、建立技术习惯、理解上线责任、共同承担问题、关注真实用户，再将经验沉淀到 AI 协作、Blogflow 与 verify。

已确认技术方向为 Three.js 加项目自用的简单引擎。游戏在博客仓库内独立维护于 `games/career-rpg/`，源码、设计、美术和测试集中在该目录；运行产物导出至 `docs/`，博客继续直接部署 GitHub Pages。游戏资源仅进入游戏页时加载。采用固定俯视镜头、像素人物与简单场景的 2.5D 表现。玩法以走动、观察、对话及情境互动为主。

当前先完善南京首次上线样章的 Web 体验与像素美术。样章约 2～3 分钟、全旅程 8～12 分钟仅作节奏预期，由试玩校正。暂不制作战斗、装备、技能树、多人、排行榜和后台服务。

## 美术方向提案

### 所有场景共用的交互表现（2026-11-05）

任务感叹号需与背景明显区分：亮黄色、深色轮廓，放在电脑上方而非贴着桌面小道具；轻缓上下浮动。减少动态效果偏好开启时停浮动，仍保持醒目。接取后消失的状态规则不变。

办公场景还需坐在电脑前打字的姿态与动画，不能只用站立或行走图替代工作状态。坐姿与工位椅子对齐，交互状态切换不得穿过桌子或遗留输入。

用户试玩后明确：对话使用发言者头部附近的气泡；人物走动需对应前后左右方向；关键人物及同伴实际在场、可接近交互；办公场景增加工位，形成有人工作的环境；电脑任务显示黄色感叹号，实际接取后消失；剧情支持紧张、开心的表情变化。后续各场景均须遵守，通过共用角色、气泡、任务标记、表情机制及场景配置实现。

方向为安静、有人生活痕迹的像素 RPG。三城通过生活场所与时间变化区分：合肥宿舍和初创办公室、南京办公室与深夜书桌、杭州各阶段的工作与使用现场。优先刻画真实记忆，城市地标仅作辅助。

| 项目 | 初始提案 |
| --- | --- |
| 镜头 | 固定正交俯视三分之四视角；地面轴向排布，避免菱形等距地面 |
| 像素尺度 | 地图以 16×16 逻辑像素格为起点；角色约 16×24，脚底统一作为位置与遮挡基准 |

概念图只用于审阅方向，不能视为符合上述像素尺寸的生产素材。正式素材需要重制或规整到固定网格，独立验证透明边缘、帧对齐与导出结果。Three.js 的实际像素呈现需样章验证，不能仅凭概念图认定可实现相同效果。

美术审阅顺序：南京办公室整体 → 主角前后左右轮廓 → 对话框与手机布局 → 合肥宿舍和南京深夜的昼夜对照 → 扩展其他城市。当前先产出概念板，不批量制作全旅程资源。

## 南京样章分镜

| 状态 | 玩家动作 | 场景反馈与下一步 |
| --- | --- | --- |
| office | 进入办公室、走到电脑、交互 | 可打开论坛；其他物件只作观察，不阻塞任务 |
| report | 阅读用户无法登录的反馈 | 确认后进入故障事件；首次反馈不能被重复触发 |
| incident | 见到无法登录的演示 | 短暂停顿表达呆住，随后 CTO 加入；随时可以继续，不强制长等 |
| investigation | 与 CTO 查看线索 | 现阶段只确定共同排查结构；真实根因未补齐前，不设计具体技术谜题 |
| restored | 确认故障恢复，读同事安慰 | 两小时通过转场交代，不模拟真实等待；对白属于回忆改写 |
| learning | 确认补测试、查看坑点注释 | 工作手册增加记录；不要求玩家编写真实代码 |
| complete | 查看手册，结束或重玩 | 显示章节完成；未来衔接南京夜读，目前不制作完整后续章节 |

无论跳过文字、刷新、重进或切换窗口，剧情事实和完成条件保持一致。跳过只压缩表达，不跳掉事件结果。工作手册记录经验，不采用经验值和道德分数。

## 技术边界提案

Three.js 负责渲染；简单引擎只负责输入、固定步长更新、碰撞、交互、场景生命周期及资源释放；剧情模块持有可序列化的状态，渲染不反向决定剧情。HTML/CSS 负责文本和菜单。

逻辑使用固定步长，渲染频率独立。切后台时暂停并清空按键状态，回来后不补跑长时间积累。脚本事件以稳定 ID 表达，可重复载入；持久化只保存章节、事件标记与稳定检查点，不序列化 Three.js 对象。

第一版存档回到最近稳定检查点，可重复呈现短对话，但不得丢失已完成事件。使用独立版本与命名空间，损坏、旧版本或存储不可用时提供重新开始／本次继续，不能白屏。重玩只清除游戏自己的存档。

依赖固定版本、本地提供并保留许可，具体版本在实现前核实。维护时允许单独预处理依赖和图集，产物提交到 docs，Pages 不增加构建流程。游戏引擎不提前扩成通用框架，不引入物理引擎、联网 AI 或服务端。
