# 南京主线核对方案

2026-11-08。依据[两批试玩反馈](./review/2026-11-08-nanjing-playtest.md)整理。作者已核对：“系统日志是在自己的电脑上查询；剩下的两处是对的。”本轮开始按此实施，修复状态与证据见 handoff。

## 南京要讲什么

第一次做 C 端上线，用户在论坛反馈无法登录。我不知所措，CTO 叫我过去并开始排查；我查看服务器日志，确认当天哪些用户出现问题。整整两小时后问题才恢复。团队安慰我，后来补了测试、写了坑点注释。

事故处理原则是：先止血、保存现场、排查日志，同时安抚用户。具体止血方式、现场内容和事故根因未提供，先作为原则表达，不编造回滚操作、报错、账户或用户数量。安抚用户和团队安慰主角分别表达，不能用后者替代前者。

## 已核对的完整主线

| 步骤 | 玩家做什么 | 页面和文案 | 完成后去哪里 |
| --- | --- | --- | --- |
| 1. 进办公室 | 走到左上自己的电脑 | 目标条提示「去左侧电脑，打开用户论坛」；不再另开同句对白 | 自己的电脑 |
| 2. 看到反馈 | 按 E 直接阅读论坛 | 保留“论坛里，有用户说无法登录。这是我第一次面对真实的线上 C 端用户。”，删除工位日常与书上读过用户的括号句。取消「选择一项，读完后再确认」菜单 | 确认后进入反应 |
| 3. CTO 叫我 | 阅读一次反应，Enter 收起 | 「我盯着登录框不知所措，这时 CTO 把我叫了过去。」不再重复论坛反馈与省略号 | 走到 CTO 身边 |
| 4. 开始分工 | 在 CTO 椅旁按 E | 直接进入「在 CTO 排查的时候，我开始去查日志，看看今天有哪些用户出现问题。」不再先点「过去看看」确认。事故处理原则明确呈现，但不写成未确认的具体历史操作 | 回自己的工位查日志 |
| 5. 查询、分析日志 | 在自己的电脑按 E，查看一次日志分析叙述并确认 | 动作为「查询、分析服务器日志」。这一步有明确结果：完成作者的日志排查部分；不伪造真实日志样本。删掉重读论坛、抄 CTO 记录、记真实用户三个任务和所有「记下来」重复页 | 目标条提示回 CTO；无 0/3、1/3、2/3、3/3 |
| 6. 故障恢复 | 回 CTO，按 E | 直接显示「整整两小时后，问题才恢复。」再保留团队安慰主角的事实。不再显示“这轮排查先到这里”“笔记本还有没记下的” | 事故段收束 |
| 7. 复盘与章末 | 阅读简短复盘；技能收集不强制跑腿 | 保留“后来，我们补了测试，也补了注释，说明这里为什么会踩坑。”删除跑去中间电脑看两份材料、再去书架确认的 0/2 任务。手册和技能保留为收束/可选收集，不卡主线 | 南京本章完成；建议下一步从南京去杭州 |

这条主线只保留真正有作用的动作：看反馈、找 CTO、查日志、回 CTO。目标条负责指路，对话负责剧情；操作成功后不再把目标复制成新对白，也不通过重复“记下来”凑进度。

“安抚用户”贯穿故障处理，可在同伴的有效提示或处理原则中明确出现。没有当时的原话时不伪造给用户发送过的具体消息。

## 交互点与物理呈现

| 对象 | 用途 | 要保持的画面关系 |
| --- | --- | --- |
| 左上自己的电脑 | 论坛与服务器日志 | 坐姿落在自己的椅内；交谈与阅读不能变成蹲在椅面上 |
| 中间 CTO | 发起排查、故障恢复 | 主角站在椅旁，不占 CTO 座位，也不与 CTO 重叠 |
| 中间电脑 | CTO 的工作现场；若保留复盘收集，应有真实关联 | 不再要求主角来回抄记录；不可出现已无任务作用的确认菜单 |
| 三位坐着的人物 | 维持办公状态，按阶段提供有效回应 | 分清脚底与臀部锚点，椅背按正确层级遮挡坐姿；优先修复位置、裁切和遮挡，不先重画人物 |
| 下排桌椅与显示器 | 可见家具和碰撞边界 | 站立角色不能踏到显示器、桌面或椅面上；桌前、桌后遮挡关系正确 |
| 技能闪点 | 仍需玩家收集的技能入口 | 闪点、触发事件、实际家具使用同一位置依据；不能悬在通道上。若自动收束该技能，就不保留无对象的闪点 |
| 章末入口 | 继续探索、手册、重玩、去下一章 | 不再以“回看合肥→南京”阻塞南京完成；合肥→南京地图属于前一章进入南京时的过场 |

## 已定位的流程原因与待验证的视觉原因

- 主线混入了「重读反馈、抄记录、确认影响、补测两项、写手册、回看来时路」多组检查清单。`accept()` 完成同状态事件后又打开「已经记下」并重复任务目标，`openConversation()` 又先打开选择菜单，造成多层无新增信息的对白。
- 当前「CTO 排查 3/3」用三次查看/记录作为前置，未体现作者补充的真实日志分工；用户已经要求删除。
- 技能闪点按 skill.role 找物件；CI 技能使用 `ci_desk`，实际学习事件在 `cto-pc`，其独立 `ci-notes` 物件与 iconAt 在通道上。触发点、收集点与闪点没有统一。
- 坐姿优先检验三个原因：家具前景缺失；图集底部是脚底/臀部而锚点未区分；坐姿比例和裁切不匹配椅子。每次只改一个变量，实际截图验证，不把 `posture='seatedTyping'` 当成坐姿正确。
- 右下桌子的碰撞边界与图中显示器/桌面范围不一致，当前能走到 `(294,155)` 盖住显示器；同时渲染只有背景再画人物，缺少家具前景。两者分别修复和验证。

## 作者已确认的范围

1. 系统日志在自己的左上工位查询，CTO 继续在中间排查。
2. 事故恢复后保留简短复盘和手册/技能收集，去掉补测 0/2 与写手册跑腿任务；技能收集作为可选内容，不阻塞主线。
3. 复盘结束就完成南京篇，下一步去杭州；不再把合肥→南京地图放在南京章末作为必做任务。

## 实施与验证

先修改事件与对白，再同步旧存档兼容，最后生成发布副本。保留旧章节进度，特别检查 report、investigation 各种部分完成状态、learning、journey 和正在打开的旧菜单；删除任务后不能让存档卡在无入口的前置条件上。

浏览器从全新存档仅用真实键盘走完整新主线，逐步记录实际正文、选项、状态、坐姿与家具遮挡；再走旧存档恢复、取消/确认重玩、技能收集、章末和南京→杭州分支。每个保留分支交付截图，失败和未执行项明确标注。

座椅检查分别看三位 NPC 与主角办公，站位检查靠近 CTO 和两侧同事，碰撞检查在桌前、桌后与四侧接近显示器。技能检查同时核对解锁事件、收集入口和实际画布上的闪点。共用渲染与输入如有修改，再检查合肥与杭州。

全仓运行 `python3 scripts/verify.py`，并执行核对后的南京正式浏览器回归。截图继续存仓库外，只给 PR 附规定的桌面/窄屏图；游戏仍等作者明确说「合」后合并。
