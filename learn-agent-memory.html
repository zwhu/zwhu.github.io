Agent 记忆流程讲解

记忆系统 · 流程与自测 · 整理于 2026-10-27

以 TencentDB-Agent-Memory 为例，跟随一个约束走过对话回流、记忆提炼、权限管理与新会话召回。

示例 · 已接入并启用记忆 1 / 6

首次会话：告诉 Agent 一个约束

输入
“旧鉴权还被移动端使用，先别重构。”

产物
当前会话中的回答
Proxy 位于 Agent 与模型之间，承担接入、身份处理和上下文注入。

四个模块，各负责什么？

MemoryProxy
位于 Agent 与模型之间，处理接入、身份、上下文注入与对话回流。
MemoryCore
保存对话和记忆，通过异步管线提炼不同粒度的记忆，并管理绑定与权限校验。
MemoryKnowledge
处理 Wiki、代码图谱等知识内容，为按需取用提供支持。
MemoryPanel
提供资产与 Agent 的管理入口；分享给团队和绑定给 Agent 是两个独立动作。

跟读源码：从注入入口开始

在 TencentDB-Agent-Memory 仓库中，从 MemoryProxy/src/injection/injectors/tdai-profile-memory-injector.ts 开始，跟踪 L3 内容与 L2 目录如何注入模型上下文。

  1. 先看输入：当前身份、Agent 绑定和可用记忆。
  2. 再看输出：L3 内容与 L2 目录；区分目录和全文。
  3. 跟踪按需查询：L2 全文、L1 细节和知识内容何时被取用。
  4. 回到一轮结束的入口，确认对话如何回流至 Core。

这里是原笔记的阅读路线；实现细节以你持有的源码版本为准。

用户说“旧鉴权暂时不能重构”。一轮结束后，哪个模块负责保存对话并异步提炼可复用约束？
